# HU12 — Recomendación de modelo de autobús por trayecto

## Descripción

El Director de Operaciones (COO) recibe una recomendación de modelos de autobús ordenados por adecuación para un trayecto específico. La recomendación se basa en la demanda histórica de afluencia del corredor (datos SEMOVI) cruzada con el catálogo de modelos del sistema. El resultado incluye justificación por capacidad vs. demanda y marca los modelos que no alcanzan la capacidad mínima requerida.

---

## Endpoint

### `GET /api/routes/{routeId}/bus-model-recommendation`

**Parámetros de ruta:**

| Parámetro  | Tipo   | Descripción               |
|------------|--------|---------------------------|
| `routeId`  | String | ID GTFS de la ruta (ej. `B_CMX0300L1`) |

**Query params:**

| Parámetro         | Tipo   | Default | Descripción                         |
|-------------------|--------|---------|-------------------------------------|
| `targetOccupancy` | Double | `0.80`  | Ocupación objetivo (0.60–0.95)      |

**Respuesta 200:**

## Lógica de negocio

### Mapeo afluencia → ruta GTFS

La tabla `afluencia_metrobus` almacena la línea como `"linea N"` (ej. `"linea 1"`). Se mapea al `route_short_name` de la tabla `routes` para agencia `MB`:

```
afluencia.linea = "linea " + route.route_short_name.toLowerCase()
```

### Fórmulas

```
peakHourDemand  = round(avgDailyDemand × 0.12)
busesPerHour    = round(60 / frequencyMinutes)   [default: 10 si no hay datos]
requiredCapacity = ceil(peakHourDemand / (busesPerHour × targetOccupancy))
minAutonomyKm   = distanceKm × 2
```

### Criterio de adecuación

Un modelo es **elegible** si:
- `passengerCapacity >= requiredCapacity`
- `autonomyKm >= minAutonomyKm`

### Ordenamiento

1. Modelos elegibles primero, ordenados por `unitCostUsd` ASC (más económico = mejor rango).
2. Modelos no elegibles al final, ordenados por `passengerCapacity` DESC (el que más se acerca al requerimiento primero).

El primer modelo elegible recibe `recommended = true`. Si ninguno es elegible, `recommended` permanece `false` en todos (AC3).

## Arquitectura

```
RouteResource
  └── RecommendBusModelUseCase
        ├── RouteRepository.findByIdWithTimeComparison(routeId)
        ├── AfluenciaMetrobusRepository.findAvgDemandByLinea(linea)
        └── BusModelRepository.findAll()
```

**Capas involucradas:**
- `interfaces/rest/RouteResource` — recibe HTTP, delega al use case, traduce excepciones
- `application/usecase/RecommendBusModelUseCase` — algoritmo de recomendación
- `domain/models/BusModelRecommendation`, `BusModelRank` — modelos de resultado
- `application/exception/NoDemandDataException` — cuando no hay datos de afluencia para la ruta
- `infrastructure/repository/RouteRepositoryImpl.findByIdWithTimeComparison` — query nativa con distancia y frecuencia
- `infrastructure/repository/AfluenciaMetrobusRepositoryImpl.findAvgDemandByLinea` — agregación AVG por tipo de día
