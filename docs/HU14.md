# HU14 — Editar especificaciones de modelo en catálogo

## Descripcion

El Administrador puede modificar cualquier campo de un modelo ya registrado en el catálogo para corregir o actualizar su información. Los cambios se guardan y se reflejan de inmediato en todas las vistas que consumen el catálogo. El sistema devuelve un mensaje de confirmación al guardar correctamente.

## Endpoints

### PUT /api/bus-models/{id}

Actualiza los campos de un modelo de autobús existente. Solo se actualizan los campos enviados en el body (actualización parcial).

**Autenticación:** No requerida.

**Path param:** `id` — Long, identificador del modelo.

**Body (JSON):**

```json
{
  "name": "Yutong E12PRO Actualizado",
  "autonomyKm": 350.00,
  "passengerCapacity": 90,
  "unitCostUsd": 450000.00
}
```

Todos los campos son opcionales. Un campo `null` o ausente conserva su valor actual.

**Respuesta exitosa (200):**

```json
{
  "message": "Modelo actualizado correctamente",
  "model": {
    "id": 1,
    "name": "Yutong E12PRO Actualizado",
    "manufacturer": "Yutong",
    "fuelType": "ELECTRIC",
    "autonomyKm": 350.00,
    "passengerCapacity": 90,
    "unitCostUsd": 450000.00,
    "batteryCapacityKwh": 352.08,
    "energyConsumptionKwhKm": 1.0000,
    "fuelConsumptionLKm": 0.0000,
    "maintenanceCostPerKm": 0.1200,
    "co2EmissionsGKm": 0.00
  }
}
```

**Errores:**

| Codigo | Condicion                          | Mensaje                          |
|--------|------------------------------------|----------------------------------|
| 404    | No existe un modelo con ese `id`   | Modelo de bus no encontrado      |
| 500    | Error inesperado del servidor      | Error inesperado                 |

## Campos actualizables

| Campo | Tipo | Descripcion |
|-------|------|-------------|
| `name` | String | Nombre del modelo |
| `autonomyKm` | BigDecimal | Autonomía en kilómetros |
| `passengerCapacity` | Integer | Capacidad de pasajeros |
| `unitCostUsd` | BigDecimal | Costo unitario en USD |

## Logica de Negocio

1. Se verifica que el modelo exista por `id`. Si no existe se lanza `BusModelNotFoundException` → 404.
2. Se construye un objeto parcial con solo los campos del DTO; los campos no enviados quedan en `null`.
3. La implementación del repositorio aplica solo los campos no-null al entity JPA existente (patch semántico).
4. Se actualiza `updated_at` con la fecha y hora actual.
5. Se retorna el modelo completo con todos sus campos tras la actualización.

## Arquitectura

```
PUT /api/bus-models/{id}
    └── BusModelResource (interfaces/rest)
            └── UpdateBusModelUseCase (application/usecase)
                    └── BusModelRepository.findById()  — verificar existencia
                    └── BusModelRepository.update()    — persistir cambios
                            └── BusModelRepositoryImpl (infrastructure/repository)
                                    └── EntityManager.find()
                                    └── Aplicación parcial de campos no-null
                                    └── EntityManager.flush()
                                    └── BusModelMapper.toDomain()
```

- AC1: El administrador puede modificar cualquier campo de un modelo ya registrado (nombre, autonomía, capacidad, costo).
- AC2: Los cambios se guardan y se reflejan de inmediato en todas las vistas que consumen el catálogo.
