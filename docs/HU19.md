# HU19 — Comparación de Tiempos Estimados vs Programados por Ruta

## Descripción

El Director de Operaciones (COO) necesita comparar los tiempos estimados de recorrido contra los tiempos programados en el GTFS por ruta, con el objetivo de identificar ineficiencias operativas. El sistema muestra una tabla comparativa que destaca las rutas con mayor variación entre ambos tiempos.

---

## Endpoints

### `GET /api/routes/travel-times`

Devuelve la comparación de tiempos por ruta, calculados a partir de los datos GTFS almacenados.

**Autenticación:** `Authorization: Bearer <Firebase ID Token>`

**Parámetros:** ninguno

**Respuesta exitosa `200 OK`:**

```json
[
  {
    "routeId": "L1",
    "routeShortName": "L1",
    "routeLongName": "Indios Verdes - El Rosario",
    "distanceKm": 28.5,
    "scheduledTimeMinutes": 79,
    "estimatedTimeMinutes": 86,
    "avgSpeedKmH": 21.6,
    "variabilityPercent": 8.9,
    "frequencyMinutes": 3
  }
]
```

| Campo | Tipo | Descripción |
|---|---|---|
| `routeId` | `string` | Identificador GTFS de la ruta |
| `routeShortName` | `string` | Nombre corto de la ruta (e.g. "L1") |
| `routeLongName` | `string` | Nombre largo de la ruta |
| `distanceKm` | `double` | Distancia total de la ruta en km (de `shapes.shape_dist_traveled`) |
| `scheduledTimeMinutes` | `int` | Tiempo programado en minutos según GTFS `stop_times` |
| `estimatedTimeMinutes` | `int` | Tiempo estimado según velocidad de referencia |
| `avgSpeedKmH` | `double` | Velocidad promedio basada en el tiempo programado |
| `variabilityPercent` | `double` | Variación porcentual entre estimado y programado |
| `frequencyMinutes` | `int` | Frecuencia mínima en minutos (de `frequencies.headway_secs`), 0 si no hay datos |

**Errores:**

| Código | Causa |
|---|---|
| `500` | Error al consultar la base de datos |

---

## Lógica de negocio

### Tiempo programado (`scheduledTimeMinutes`)

Derivado de la tabla GTFS `stop_times` para un viaje representativo por ruta:

```
scheduledTimeMinutes = MIN( MAX(arrival_time) − MIN(departure_time) ) por trip
                       agrupado por route_id
```

Los tiempos en `stop_times` están en formato `HH:MM:SS`. Se convierten a segundos con `TIME_TO_SEC()` y se divide entre 60.

### Tiempo estimado (`estimatedTimeMinutes`)

Calculado en `GetRouteTravelTimesUseCase` usando una velocidad de referencia operativa:

```
estimatedTimeMinutes = round( distanceKm / REFERENCE_SPEED_KMH × 60 )
```

Constante: `FleetConstants.REFERENCE_SPEED_KMH = 20.0 km/h`

### Velocidad promedio (`avgSpeedKmH`)

```
avgSpeedKmH = distanceKm / (scheduledTimeMinutes / 60)
```

Se redondea a 1 decimal. Si `scheduledTimeMinutes = 0`, retorna `0.0`.

### Variabilidad (`variabilityPercent`)

```
variabilityPercent = (estimatedTimeMinutes − scheduledTimeMinutes) / scheduledTimeMinutes × 100
```

- **Positivo**: el estimado es mayor que el programado → la ruta opera más lento que la estimación de referencia.
- **Negativo**: el estimado es menor que el programado → la ruta opera más rápido que la estimación de referencia.

Se redondea a 1 decimal. Si `scheduledTimeMinutes = 0`, retorna `0.0`.

### Frecuencia (`frequencyMinutes`)

```
frequencyMinutes = MIN(headway_secs) / 60  agrupado por route_id
```

Retorna `0` si la ruta no tiene datos en la tabla `frequencies`.

## Arquitectura

```
RouteResource (interfaces/rest)
    └── GetRouteTravelTimesUseCase (application/usecase)
            └── RouteRepository.findAllWithTimeComparison() (domain/repository)
                    └── RouteRepositoryImpl — native SQL query (infrastructure/repository)
                            ├── routes
                            ├── trips
                            ├── shapes       ← distanceKm
                            ├── stop_times   ← scheduledTimeMinutes
                            └── frequencies  ← frequencyMinutes
```

**Capas involucradas:**

| Capa | Archivo | Responsabilidad |
|---|---|---|
| REST | `RouteResource.java` | Exponer `GET /api/routes/travel-times`, manejar errores HTTP |
| Use Case | `GetRouteTravelTimesUseCase.java` | Calcular `estimatedTimeMinutes`, `avgSpeedKmH`, `variabilityPercent` |
| Domain | `RouteTimeComparison.java` | Modelo de datos puro |
| Domain | `RouteRepository.java` | Puerto (interfaz) con `findAllWithTimeComparison()` |
| Infrastructure | `RouteRepositoryImpl.java` | Query nativa MySQL que une 5 tablas GTFS |

## Criterios de aceptación verificados

| AC | Descripción | Implementación |
|---|---|---|
| AC1 | Tabla comparativa entre tiempos estimados y programados por ruta | `GET /api/routes/travel-times` retorna ambos campos |
| AC2 | Rutas con mayor variación destacadas | `variabilityPercent` calculado; el frontend aplica color coding |
| AC3 | Datos provenientes de fuentes GTFS | `scheduledTimeMinutes` de `stop_times`; `frequencyMinutes` de `frequencies`; `distanceKm` de `shapes` |
